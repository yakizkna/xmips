# Xmips（Go 复刻版）使用说明

本版本使用 Go 重新实现了《Xmips指令系统与ABC汇编语言》中的 Xmips 教学模拟系统，指令集、指令编码格式与 ABC 汇编语义与原版保持一致，用于学习指令系统、汇编语言与操作系统原理。行为验证示例为 `SUM.cupa` 和 `BUBBLE_INT.cupa`。

## 一、运行方法

本版本没有 `Xmips.exe` 可执行文件，需要先编译再运行：

```bash
cd xmips_go
./build.sh                # 编译 src/ 并把可执行文件拷贝到 Xmips/xmips
```

运行（**可从任意目录直接调用**，运行根目录 = 可执行文件所在目录）：

```bash
cd Xmips && ./xmips              # A. 无参数 → 从 file/run.list 读取要运行的程序
./xmips XXX.cupa                 # B. 指定程序：优先当前目录，其次 Xmips/file/ 目录
./xmips /绝对/路径/XXX.cupa       # C. 指定程序的绝对或相对路径
./xmips update                   # D. 重建系统函数库（重汇编 sysfun/*.scp 生成 .co）
```

> 注意：`config.ini`、`sysfun/`、`file/` 均自动定位到“可执行文件所在目录”（即 `Xmips/`），与当前工作目录无关，因此无需再 `cd` 到 Xmips 即可直接运行。用户 `open` 的文件为真实宿主文件（相对当前工作目录或绝对路径），可直接读写主机任意路径。建议把 `Xmips/xmips`（或其符号链接）加入 PATH，即可在任何目录执行 `xmips XXX.cupa`。

默认运行 `run.list` 中登记的程序（`run.list` 位于 `file/` 目录）。

## 二、系统目录结构

Xmips 系统目录（`xmips_go/Xmips`）下包括：

| 项目 | 说明 |
|------|------|
| 可执行文件 | `Xmips/xmips`（位于运行目录内经 `./build.sh` 生成） |
| 配置文件 | `config.ini` |
| 用户程序目录 | `file` |
| 系统程序目录 | `sysfun` 存放系统函数库，用户不可修改 |

除此之外，汇编产生的字符码文件（扩展名为 `.co`）也会生成在当前运行目录下。

## 三、路径设置和参数配置

### 3.1 路径设置

1. 所有的用户汇编源文件都要保存到 `Xmips/file` 目录下。
2. 运行列表文件 `Xmips/file/run.list` 登记了要汇编和运行的程序名。
3. ABC 汇编源程序对扩展名不做要求，但推荐使用 `.abc` 或 `.cupa`。
4. `run.list` 必须以 `end`/`END` 结尾，`end`/`END` 之后的内容将不会再被读取。

### 3.2 参数配置

参数信息保存在 `Xmips/config.ini` 文件中，用户可以修改。可配置参数如下：

- **`<1> delayMode` —— 访存延时模拟**

  由于在实际的计算机中，访问主存比访问寄存器慢很多，故 Xmips 系统提供了访存延时模拟的功能。

  ```ini
  delayMode = 0 ; 访存延时模拟关闭（运行时体现访存和访问寄存器的速度差异）
  delayMode = 1 ; 访存延时模拟开启
  ```

- **`<2> displayMode` —— 显示模式（本版本为三种取值）**

  ```ini
  displayMode = 0 ; 隐藏进程加载内容，汇编过程中不显示源程序
  displayMode = 1 ; 显示全部信息，汇编过程中显示源程序
  displayMode = 2 ; 只显示标准输出和系统错误，结束后不询问是否显示数据段，直接退出
  ```

- **`<3> reportLevel` —— 系统运行状况报告等级**

  Xmips 系统运行过程中会显示运行状况信息（汇编语法错误、中断方式、进程运行完毕等）。

  ```ini
  reportLevel = 0 ; 只报告 Warning 和 Error
  reportLevel = 1 ; 报告 Normal 和 Error
  reportLevel = 2 ; 报告全部信息
  ```

- **`<4> updateSysfun` —— 重建系统函数库（已改为独立命令）**

  系统函数库提供了一组用户可以通过软中断调用的 API，用户不可修改。系统函数以 `.scp` 源程序形式保存在 `sysfun/` 目录，汇编后生成 `.co` 字符码文件。普通运行时直接加载 `.co`；若修改了 `sysfun` 下的 `.scp` 源程序或删除了 `.co`，用独立命令重建系统库：

  ```bash
  ./xmips update   # 重新汇编 sysfun/*.scp 生成 .co（应在运行目录下执行）
  ```

  该命令仅重建系统函数库并退出，不对用户程序做任何执行。

- **`<5>` 内存大小参数**

  ```ini
  codeSize         ; 用户进程代码区长度（字）
  dataSize         ; 用户进程数据区长度（字）
  stackSize        ; 用户进程栈区长度（字）
  sysfunCodeSize   ; 系统函数代码区长度（字）
  sysfunDataSize   ; 系统函数数据区长度（字，运行时指向调用者的数据段）
  sysfunStackSize  ; 系统函数栈区长度（字）
  ```

  当编写的程序较大时，可相应调大 `codeSize`、`dataSize`、`stackSize` 等参数。

- **`<6>` 调度参数**

  ```ini
  cycleTimes   ; 时间片大小：每个时间片最多执行的指令数
  pcbNum       ; PCB 数量：系统最大并发进程数
  ```

- **`<7> bitMode` —— 机器字长**

  机器字长决定通用寄存器与内存中整数的有效位数与进位行为，影响 `ADD/SUB/MUL` 等算术运算的溢出回绕以及 `SHL/SHR/ROL/ROR` 位移/循环移位的操作宽度。

  ```ini
  bitMode = 64   ; 64 位整数（默认）。数值按 64 位带符号整数处理，溢出不回绕
  bitMode = 32   ; 32 位整数。算术运算溢出按 2^32 回绕（等价于 C 的 int），
                 ; SHL/SHR/ROL/ROR 按 32 位运算
  ```

**`config.ini` 文件格式要求：**

1. 每一行不能有空格，如“=”和参数数值之间不可有空格；
2. 必须以 `end` 结尾（`end` 之后的内容不再读取）；
3. 以分号（`;`）开头的行是注释行；参数值之后也可用分号（`;`）添加行内注释。

## 四、系统函数约定

系统函数：`Xmips/sysfun` 目录下的 `.scp` 系统函数命名为 `INT_xx.scp`（xx 为系统调用号）。当前仅 INT 10（冒泡排序）使用 `.scp` 系统函数：

```
INT_10.scp  INT 10 系统调用：冒泡排序（使用 #11、#12）。
```

> INT 13（输出字符串）、INT 14（标准输入）以及 INT 15~18（文件/Socket）均由 dispatcher 原生执行（无 `.scp`、不占用 PCB），无需 sysfun 目录源文件。

系统调用号与所用寄存器保持一致，便于记忆：

```
INT 10  使用 #11、#12
INT 13  使用 #11（字符串起始地址）
INT 14  使用 #12（缓冲区大小）、#11（缓冲区起始地址）→ 返回标志放 #13（#13=0 EOF，#13=1 缓冲满）
```

- INT 14（dispatcher 原生）从 stdin 逐字符读入存入缓冲区，直到读到 EOF 或缓冲区满结束；返回 `#13=0`（EOF）或 `#13=1`（缓冲满）。若需交互式回车结束输入，可在用户程序中每次读 1 个字符（`#12=1`）并自行判断回车（参考 `GREET.cupa`）。
- 注意：输入寄存器 `#14` 禁止用户程序读取，读取会触发系统错误 `RES=198`（非法访问）；用户程序应通过 INT 14 从 stdin 间接获取输入。

### 文件与真实网络 Socket（INT 15~18，dispatcher 原生执行，无 `.scp`）

调用约定：`#10`=调用号，`#11/#12`=参数，fd 用 `#9`（返回值也是 `#9`）。

| 调用号 | 功能 | 传入 | 返回 `#9` |
|--------|------|------|-----------|
| 15 | open | `#11`=路径串地址(数据段 0 结尾)，`#12`=模式 | fd |
| 16 | read | `#11`=缓冲地址，`#12`=最大长度，`#9`=fd | 实际字节数（0=暂无数据/EOF） |
| 17 | write | `#11`=缓冲地址，`#12`=写入长度，`#9`=fd | 实际写入字节数 |
| 18 | close | `#9`=fd | — |

open 路径前缀：

- `sock:host:port`：TCP 客户端；端口 443 自动启用 TLS（cupa 无需关心加密）。
- `tlssock:host:port`：TCP 客户端；强制 TLS（ServerName=host）。
- 其它：文件，映射到真实宿主文件（相对当前工作目录或绝对路径），直接读写主机任意路径。

`#12` 模式：`0`=只读，`1`=写（截断），`2`=读写追加（仅文件有效）。fd 从 3 起。

**阻塞语义**由单进程模式决定（`./xmips xxx.cupa` 直跑，或 run.list 恰有 1 个文件）：

- 单进程：socket read 阻塞等待，受 `sockTimeout`（默认 2000ms）超时保护，超时返回 0，不会卡死。
- 多进程：socket read 非阻塞，无数据时返回 0 并让出时间片（放就绪队尾，避免忙自旋）。

socket write 与 connect/握手均受 `sockTimeout` 约束。

错误码：

| 错误码 | 含义 |
|--------|------|
| -1 | open 失败 / 非法路径 |
| -2 | 非法 fd |
| -3 | 连接失败 |
| -4 | write 缓冲满 |
| -5 | socket 关闭 / 读写错误 |

示例：`file/NETTOUR.cupa`（HTTPS 抓取 `https://ace.yakidev.top/tour` 并写入 `tour.html`）。

配置项：`sockTimeout`（socket 超时毫秒）；`diskRoot` 为预留项（不再强制限定磁盘目录）。

## 五、编辑汇编源程序

要运行的用户源程序必须建立在 `Xmips/file` 目录下。

1. 汇编源程序必须以 `END` 语句结尾。
2. 保存源程序后，在 `file/run.list` 文件中登记要运行的源程序名。
3. 按“一、运行方法”重新运行程序即可汇编并执行。
